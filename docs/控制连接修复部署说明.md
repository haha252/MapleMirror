# 控制连接修复部署说明

2026-10-04，本地修复基于 `5b4339a`，尚未提交或部署。包内 `BUILD-INFO.json` 记录独立修复版本、源码快照 SHA256 与实际构建参数；二进制的 `vcs_modified=true` 如实表示工作区构建。Linux amd64 两个角色分别为 `mirror-master`、`mirror-node`。

## 已验证的行为

- 接收预算 128 条 / 8 MiB 估算大小；读取与数据库处理分开，Ping/Pong 可以持续运行。
- 节点持久上报各类型 4 条在途；主节点最多 4 份不同在途授权；有效 ACK 释放窗口并立即补充。超时重试保持原始载荷。
- 库存每秒最多入队一段，最终 ACK 确认整份快照，超时重发相同快照；状态报告先启动。
- 正确重复/迟到 ACK 幂等处理，旧状态 ACK 不误确认新状态；断线取消会话数据库工作，保留持久 outbox。
- `go test ./...`、三个控制包完整 race 检查及最终新增场景 race 均通过；71 条突发、1,000 事件断线恢复、五节点并发、数据库阻塞时 Ping、超过出站预算的库存、授权窗口/重复 ACK 均通过。
- e600698 主节点及 601fdda 节点的历史控制处理与独立历史队列代码分别与修复端配合，1,000 事件恢复测试通过。这不是完整旧二进制、生产 mTLS 网络或真实下载验收。

修复没有改动协议字段、数据库 schema 或升级代码。当前完整程序基于较新的 `5b4339a`，部署时仍应确认现有主节点数据库可被该基线版本读取；安装脚本会先做一致性数据库备份。现场首次断线原因及生产恢复效果仍待验证。

## 灰度顺序

1. 主节点保留应急回退版本，在一个故障节点安装修复节点程序，观察至少 30 分钟；积压清空、库存 ACK 前进、报告持续刷新并实际下载成功后再继续。
2. 安装修复主节点，其他节点暂时保留现有版本，观察全部节点至少 30 分钟。
3. 验收通过后逐个升级其他下载节点。任何阶段出现原有重连循环、报告停滞或下载回归，回滚该阶段程序并停止扩散。

以下为用户在目标机器执行的部署步骤，本次仅生成安装包。脚本按 `/opt/mirror-master`、`/opt/mirror-node` 标准目录工作；其他安装路径先按 `systemctl show` 与实际配置调整。

```bash
# 把 mirror-control-reconnect-linux-amd64.tar.gz 上传到 /tmp 后执行
cd /tmp
tar -xzf mirror-control-reconnect-linux-amd64.tar.gz
cd mirror-control-reconnect-linux-amd64
sha256sum -c SHA256SUMS
cat BUILD-INFO.json

# 第一个灰度下载节点：会停止服务、备份旧程序及数据库、替换并启动
sudo bash deploy.sh node

# 完成节点观察后，才在主节点上执行对应角色
# sudo bash deploy.sh master
```

脚本失败时尝试恢复旧程序并启动服务；成功时打印唯一备份目录及准确的程序回滚命令。它不更改配置或清理 outbox。备份目标数据库可能含运行身份，应继续保存在原主机受控目录。

## 只读验收

在灰度下载节点运行两次，间隔约一分钟，然后持续观察 30 分钟。VM-0-9 已确认监听 8081；其他节点端口从自身配置核对。

```bash
date -Is
systemctl show mirror-node.service --no-pager -p MainPID -p NRestarts -p ActiveState -p ExecMainStartTimestamp
journalctl -u mirror-node.service --since '10 minutes ago' --no-pager -o short-iso -n 150
curl --max-time 5 -sS http://127.0.0.1:8081/healthz
sqlite3 -readonly /opt/mirror-node/data/node-state.db <<'SQL'
.headers on
.mode column
SELECT COUNT(*) AS pending_traffic, MIN(created_at) AS oldest
FROM pending_traffic_events WHERE confirmed_at IS NULL;
SELECT COUNT(*) AS pending_terminal_status, MIN(updated_at) AS oldest
FROM local_authorizations WHERE reported_at IS NULL
AND status IN ('expired_first_connection','expired_idle','expired_max_duration');
SELECT * FROM inventory_report_cursor WHERE id=1;
SELECT COUNT(*) AS pending_results FROM pending_sync_task_results WHERE reported_at IS NULL;
SELECT COUNT(*) AS pending_manifests FROM pending_swarm_manifests;
SQL
```

主节点升级后核对会话、心跳与就绪状态：

```bash
date -Is
systemctl show mirror-master.service --no-pager -p MainPID -p NRestarts -p ActiveState -p ExecMainStartTimestamp
journalctl -u mirror-master.service --since '10 minutes ago' --no-pager -o short-iso -n 200
sqlite3 -readonly /opt/mirror-master/data/master.db <<'SQL'
.headers on
.mode column
SELECT id,public_name,state,routing_ready,last_heartbeat_at FROM nodes;
SELECT node_id,connected_at,disconnected_at,close_reason
FROM node_control_sessions ORDER BY connected_at DESC LIMIT 20;
SQL
```

验收必须同时满足：自然负载下无队列溢出或周期性重连；报告在正常周期内刷新；停止新增测试流量后真实 pending 降到零，持续生产流量下积压年龄收敛；库存 last_acked_revision 前进；抽样授权下发、实际下载、取消和 Swarm 同步正常。需要全量就绪的节点另外核对 `missing_assets=0`、`unfinished_tasks=0`、`routing_ready=1`。`active` / `issued` 历史授权总数不是待重放的终态消息数。

回滚使用安装脚本打印的旧程序路径；普通程序回滚保留当前数据库，避免丢失升级后产生的统计和库存进度。数据库快照用于灾难恢复，不作为每次程序回滚的默认操作。
