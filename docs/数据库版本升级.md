# 数据库版本升级规则

本文是 SQLite 结构变更的硬约束。主节点和下载节点数据库都使用 `database_version` 表记录当前结构版本。

## 当前基线

- 当前主节点数据库版本：`1`
- 当前下载节点数据库版本：`2`
- 空库启动时直接初始化版本 `1` 的完整结构。
- 已有旧库若尚无 `database_version`，启动时会收编为版本 `1`，并移除旧的 `schema_migrations` 记录表。

## 变更规则

1. 不得静默修改现有版本的 SQL 结构文件。
2. 任何表、列、索引、约束、触发器或初始结构语义变化，都必须提升对应数据库版本。
3. 版本只能逐级升级，例如 `1 -> 2`、`2 -> 3`，不能写跳级升级器。
4. 新程序打开旧库时必须按顺序执行所有缺失升级器，例如版本 `1` 的库部署版本 `3` 程序时，必须执行 `1 -> 2` 后再执行 `2 -> 3`。
5. 升级器必须在单个事务内执行，失败时不得推进 `database_version`。
6. 镜像资产文件仍保存在文件系统；数据库只保存资产索引、身份、控制状态、同步状态和未确认事件。

## 修改步骤

1. 在 `internal/storage/version.go` 中提升 `masterDBVersion` 或 `nodeDBVersion`。
2. 在 `versionPlan` 对应数据库类型中加入新的 `versionUpgrade`。
3. 新增升级器函数，命名建议为 `upgradeMaster1To2` 或 `upgradeNode1To2`。
4. 新增对应版本文档：`docs/数据库版本/vN.md`。每升一级都必须写一个独立文档，例如版本 `2` 必须新增 `v2.md`，版本 `3` 必须新增 `v3.md`。
5. 在版本文档里说明该版本的结构变化、升级器名称、兼容风险和验证方式。
6. 更新或新增测试，覆盖旧版本库逐级升级到当前版本。
7. 更新 `internal/storage/schema_contract_test.go` 中的结构指纹。
8. 更新本文的当前基线版本。

如果只修改查询、运行时代码或文档，不改变数据库结构，不需要提升数据库版本。

## 版本文档硬要求

- `docs/数据库版本/v1.md` 记录版本 `1` 的初始结构基线。
- 后续每一个数据库版本都必须有一个同名文档，例如 `v2.md`、`v3.md`。
- 不允许多个版本共用一篇文档，也不允许只在提交信息或代码注释中描述数据库变化。
- 测试会检查当前代码声明的数据库版本是否存在对应版本文档。
