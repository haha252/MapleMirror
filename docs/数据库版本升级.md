# 数据库版本升级规则

本文是 SQLite 结构变更的硬约束。主节点和下载节点数据库都使用 `database_version` 表记录当前结构版本，但版本文档、当前版本和升级器必须按端分开维护。

## 当前基线

- 当前主节点数据库版本：`2`
- 当前下载节点数据库版本：`3`
- 空库启动时直接初始化对应端版本 `1` 的完整结构，再由统一版本管理器逐级升级到当前版本。
- 已有旧库若尚无 `database_version`，启动时会收编为版本 `1`，并移除旧的 `schema_migrations` 记录表。

## 变更规则

1. 不得静默修改现有版本的 SQL 结构文件。
2. 任何表、列、索引、约束、触发器或初始结构语义变化，都必须提升对应数据库版本。
3. 版本只能逐级升级，例如 `1 -> 2`、`2 -> 3`，不能写跳级升级器。
4. 新程序打开旧库时必须按顺序执行所有缺失升级器，例如版本 `1` 的库部署版本 `3` 程序时，必须执行 `1 -> 2` 后再执行 `2 -> 3`。
5. 升级器必须在单个事务内执行，失败时不得推进 `database_version`。
6. 镜像资产文件仍保存在文件系统；数据库只保存资产索引、身份、控制状态、同步状态和未确认事件。

## 启动顺序与升级器边界

`storage.OpenMaster` 和 `storage.OpenNode` 打开 SQLite 后立即执行数据库版本检查和升级；升级成功后，主节点才会继续启动 admin、control、public 和同步服务，下载节点才会继续启动登记、控制连接和下载服务。

升级器只能使用以下输入：

- `context.Context`
- `*sql.Tx`
- `internal/storage` 包内的轻量 SQL helper，例如 `hasColumn`

升级器不得依赖或初始化以下对象：

- `mastercontrol.Repository`、`nodecontrol.IdentityStore` 或其他业务仓储封装。
- logger、config loader、HTTP service、runtime store、同步器、控制客户端或下载处理器。
- 任何启动后才可用的业务状态。

升级器只负责 schema 和必要的数据迁移；版本推进由统一版本管理器在升级器成功返回后写入 `database_version`。

## 修改步骤

1. 在 `internal/storage/version_plan.go` 中提升对应端的 `masterDBVersion` 或 `nodeDBVersion`。
2. 在 `versionPlan` 对应端的显式升级链里加入新的 `versionUpgrade`。
3. 在对应端的升级器目录中新增独立升级器文件：
   - 主节点：`internal/storage/upgrades/master/upgrade_vX_to_vY.go`
   - 下载节点：`internal/storage/upgrades/node/upgrade_vX_to_vY.go`
4. 新增升级器函数，按端命名：
   - 主节点：`master.VXToVY`
   - 下载节点：`node.VXToVY`
5. 新增对应端的版本文档：
   - 主节点：`docs/master/vN.md`
   - 下载节点：`docs/node/vN.md`
6. 在版本文档里说明该版本的结构变化、升级器名称、兼容风险和验证方式。
7. 更新或新增测试，覆盖旧版本库逐级升级到当前版本。
8. 更新 `internal/storage/schema_contract_test.go` 中的结构指纹。
9. 更新本文的当前基线版本。

如果只修改查询、运行时代码或文档，不改变数据库结构，不需要提升数据库版本。

## 版本文档硬要求

- `docs/master/v1.md` 和 `docs/node/v1.md` 分别记录对应端版本 `1` 的初始结构基线。
- 后续每一个端级数据库版本都必须有一个同名文档，例如 `docs/master/v2.md`、`docs/node/v3.md`。
- 不允许 master 和 node 共用一篇版本文档，也不允许只在提交信息或代码注释中描述数据库变化。
- 测试会分别检查当前代码声明的主节点和下载节点数据库版本是否存在对应端文档。

## 升级器实现标准

- 升级器文件只包含一个版本跨度的迁移逻辑，必要 helper 可以放在 `internal/storage/upgrades/master/` 或 `internal/storage/upgrades/node/` 下的同端 helper 文件中。
- 升级器必须幂等：重复执行时应通过列、表或索引存在性检查避免失败。
- 不支持自动降级；版本高于当前程序支持版本时必须拒绝启动。
- 不使用 `init()` 自动注册升级器。所有升级器必须由 `versionPlan` 的显式升级链引用。
- `internal/storage` 根目录不得继续新增 `upgrade_*` 文件，`internal/storage/upgrades/` 根目录只放跨端通用 SQL helper；端级升级器必须分别放入 `master/` 或 `node/` 子目录。
