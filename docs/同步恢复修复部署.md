# 同步恢复修复部署

适用于主节点及下载节点使用 control.v2 的部署。本次不增加数据库版本。

## 修复行为

- 节点只为仍在执行或有清单待确认的任务续租，孤立的 running 记录不会永久占用租约。
- 接受消息入队失败会持久化临时错误；旧 attempt 的结果、清单及迟到 ACK 不会覆盖新任务。
- WebSocket 读取与按顺序执行的业务处理分开，Ping/Pong 不必等待数据库处理；接收队列有上限，过载时重连并重放持久化消息。
- peer-only 分片请求可以等待 peer 冷却及源清单刷新，每个块最多等待两分钟，仍受整任务超时约束。
- 单个分片失败后，其他分片继续下载并持久化。重试会保留已验证进度。
- 主节点每 30 秒检查过期租约和到期重试，拒绝任务也会安排重试唤醒。
- 有 authoritative 清单的 v2 同步临时错误持续退避重试，最高间隔三分钟；永久错误保留失败状态。
- “重置同步”会重新调度缺失资产、清除旧 attempt 和重试次数，并停止旧任务；已验证库存和节点分片保留。
- 管理员取消会传递到实际执行任务，并防止库存对账自动恢复该任务；可以点击重试或重置同步重新开始。

## 安装

安装包为 `dist/mirror-sync-recovery-linux-amd64.tar.gz`，包含两个程序、校验文件和安装脚本。
只支持 Linux x86_64，使用 `/opt/mirror-master`、`/opt/mirror-node` 及对应 systemd 服务。
安装脚本先验证路径、校验二进制，再备份程序和 SQLite 数据库；不删除文件、分片、配置或证书。

先将同一个安装包上传到主节点和成都-01 的 `/tmp/`。

主节点执行：

```bash
cd /tmp
tar -xzf mirror-sync-recovery-linux-amd64.tar.gz
cd mirror-sync-recovery-linux-amd64
sudo bash deploy.sh master
journalctl -u mirror-master.service --since '5 minutes ago' --no-pager -n 100
```

成都-01 执行：

```bash
cd /tmp
tar -xzf mirror-sync-recovery-linux-amd64.tar.gz
cd mirror-sync-recovery-linux-amd64
sudo bash deploy.sh node
journalctl -u mirror-node.service --since '5 minutes ago' --no-pager -n 100
```

先升级主节点，再升级成都-01；其他节点可以随后逐个升级。首次升级节点会恢复中断任务并上报库存。
刷新管理面板，在成都-01 详情点击一次“重置同步”，让遗留任务按新流程重新调度。
成都无法直连 GitHub 时保持 `force_peer_download: true`，需要至少一个持有缺失分片的 peer 可访问。
所有 peer 都不可达时，新代码会保留进度并重试，仍需排查节点之间的网络连通性。

## 验收

主节点应看到成都-01 的 `missing_assets=0`、`unfinished_tasks=0`、`routing_ready=1`。
以下查询只读：

```bash
cd /opt/mirror-master
python3 - <<'PY'
import sqlite3, json
from pathlib import Path
db = sqlite3.connect(Path('data/master.db').resolve().as_uri()+'?mode=ro', uri=True, timeout=3)
db.row_factory = sqlite3.Row
sql = """
SELECT n.public_name,n.routing_ready,
 (SELECT COUNT(*) FROM target_inventory t
  LEFT JOIN node_inventory i ON i.node_id=t.node_id AND i.asset_id=t.asset_id
  WHERE t.node_id=n.id AND t.desired_state='required'
   AND (i.asset_id IS NULL OR i.state!='verified')) AS missing_assets,
 (SELECT COUNT(*) FROM node_tasks t WHERE t.node_id=n.id
  AND t.state IN ('pending','sent','running','retry_wait','failed')) AS unfinished_tasks
FROM nodes n WHERE n.public_name='成都-01'
"""
for row in db.execute(sql):
    print(json.dumps(dict(row), ensure_ascii=False))
db.close()
PY
```

如果尚未完成，节点日志及任务 `error_message` 会提供失败 peer 的 Node ID、分片和请求范围。
实际生产恢复以此查询和文件库存验证为准，不能仅凭服务 active 或临时文件大小判断。

## 回滚

安装脚本会打印实际备份目录和程序回滚命令。按该命令停止服务、恢复原程序并重新启动即可。
本次无数据库迁移，通常无需恢复数据库。保留数据库备份供故障取证，避免回退库存和任务进度。
