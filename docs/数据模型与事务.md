## 1. 文档定位

M1 已完成实现，本文件不要求为文档顺序重写有效代码。本文件从现有代码和迁移追认数据事实，并成为后续数据结构、迁移和关键事务变化的专门合同。

| 结论类型 | 含义 |
| --- | --- |
| 已实现 | 当前迁移或配置代码已经存在，启动时可创建或校验 |
| 已预留未启用 | 表或字段已存在，但对应业务尚未运行 |
| M2 预计新增 | 只有在本文件及 M2 相关合同确认后才可新增迁移或代码 |

### 3.1 核心、项目与资产表

| `runtime_kv` | `key` 主键、`value`、`updated_at` | 已创建，尚无业务写入 | 合理预留 |
| `projects` | 项目标识、公开仓库字段、保留数、预发布开关、倍率、配置摘要 | 已创建，M3 才投影配置 | 字段支持定稿合同；未实现扫描 |

- `projects`、`releases`、`assets` 存在不表示 GitHub 扫描已实现。

- M2 新建或更新的节点不得把 `routing_ready` 置为 `1`。

- `在线可路由` 只能由 M3 完整库存对账完成后的后续逻辑产生。

### 5.2 M2 预计最小配置增量

下列配置尚未实现，只能在三份合同确认后随 M2 代码加入：

| 预计新增字段 | 原因 | 最小变更策略 |
| --- | --- | --- |
| `server.enrollment_listen` | 未持客户端证书的节点不能进入强制 mTLS 控制端口领取证书 | 新增独立 TLS 1.3 受限登记监听，不降低控制端口认证 |
| `node.heartbeat_interval` | 需要明确上报频率并小于现有超时 | 新增正持续时间校验 |
| 主节点节点客户端 CA/签发 CA 路径 | 服务端需验证和签发节点证书 | 扩展 `node.tls` 配置，不记录私钥 |
| 管理 HTTPS 服务端证书与管理员客户端 CA 路径 | Bearer 令牌传输需要 TLS，高风险 API 要校验管理员 mTLS | 扩展 `admin` 配置 |
| 节点 `master.enrollment_address` | 首次登记端口与 mTLS 控制端口分离 | 扩展节点配置，领证后仅使用控制地址 |
| 节点登记码安全文件路径 | 配对码不应长期写入普通 YAML | 新增一次性输入路径或等价安全输入方案 |

当前 `server.management_listen` 限制为回环地址，比“管理网络可访问”更严格而非放宽安全。若 M2 需要远端管理网络监听，最小修正是仅允许显式管理地址绑定并继续以 `admin.allowed_cidrs`、HTTPS、管理令牌和高风险 mTLS 共同限制。

## 6. M1 与需求定稿的偏差检查

| 检查项 | 现状判断 | 影响 | 处置 |
| --- | --- | --- | --- |
| SQLite 与事务迁移基础 | 符合 | 无 | 继续以新增迁移扩展 |
| 新节点默认不可路由 | `routing_ready DEFAULT 0` 符合 | 无 | M2 测试强制保持为零 |
| 配对码不存明文 | 已有字段为 `code_hash`，符合预留 | 无 | M2 实现消费/撤销事务 |
| 证书轮换身份历史 | 现有仅单指纹字段，不足以实现轮换和吊销 | M2 无法仅靠 `nodes` 表安全验证历史证书 | M2 新增 `node_certificates` 表，不重写已有表 |
| 登记审批状态 | 现有无登记请求表 | 无法保存 CSR 审批与领取状态 | M2 新增 `node_enrollment_requests` |
| 会话防重放 | 现有无活动会话/最后确认序号表 | 无法跨重连持久判断控制消息重放 | M2 新增 `node_control_sessions` 与节点本地控制状态 |
| 库存/压力报告骨架 | 心跳仅容纳摘要压力，无库存修订报告表 | 无法单独接收库存报告合同 | M2 新增报告元数据表，不写正式库存 |
| 管理高风险身份审计 | 审计表无管理员证书摘要字段 | 无法记录叠加 mTLS 的安全主体 | M2 扩展审计字段或新增审计扩展表 |
| `assets.digest_sha256` 数据库约束 | SQL 未限定格式 | 若 M3 忽略业务校验会破坏摘要规则 | M3 写入服务严格校验；可在 M3 迁移补 CHECK/导入保护 |

以上均未表明已投入运行的 M1 行为违反需求。差异集中于后续阶段尚未实现所需结构，采用增量迁移即可处理，不需要回退 M1 有效代码。

## 8. 关键事务合同

### 8.1 M2 必须实现的事务

| 事务 | 原子操作 | 失败结果 |
| --- | --- | --- |
| 创建配对码 | 写入仅含安全哈希的配对记录、请求 ID 和到期时间；返回明文只发生在响应内 | 不产生可使用记录 |
| 消费配对码并登记 | 校验未用/未撤销/未过期，标记消费，创建唯一登记请求 | 同一码不得出现两个待审批记录 |
| 批准登记并签证 | 校验登记状态，创建节点和证书身份，写审计；节点 `routing_ready=0` | 不签出孤立证书，不生成可路由节点 |
| 禁用节点 | 更新管理状态及 `routing_ready=0`，使活动证书/会话被拒绝或关闭，写审计 | 不能留下继续接受控制消息的禁用节点 |
| 轮换证书 | 建立新证书记录、使旧证书失效、写审计并触发旧会话结束 | 不能同时保留两个活动身份而无记录 |
| 接收心跳/报告 | 校验证书映射和消息序号，保存报告或心跳并推进确认序号 | 重放不得重复产生状态副作用 |
| 离线判定 | 比较最后心跳和阈值，更新离线与 `routing_ready=0` | 重复执行幂等 |

## 10. M3 Release 扫描与同步合同

M2 控制面完成后，M3 已开始正式写入 M1 预留的项目、Release、资产、目标库存和节点库存表，并新增扫描运行状态及节点本地同步任务表。M3 仍不得启用 M4/M5 的公共下载、额度、流量或 SLA 统计。

### 10.1 `projects`、`releases`、`assets`

| 表 | M3 写入语义 | 事务要求 |
| --- | --- | --- |
| `projects` | 从 `projects.yaml` 投影启用状态、公开仓库、保留版本数、预发布开关、倍率和配置摘要 | 单项目扫描事务内 upsert；配置非法时不写半成品 |
| `releases` | 保存 GitHub Release ID、tag、预发布标记、发布时间和是否位于当前保留窗口 | 同项目同 GitHub Release ID 幂等更新 |
| `assets` | 只保存已通过可信 `sha256:` 摘要门禁的候选资产 | `digest_sha256` 必须由业务层严格校验为 `sha256:<64 hex>` 并规范化后写入 |

GitHub asset 摘要只信任 GitHub Release Assets API 响应中的 `digest` 字段。缺失、非 `sha256:`、长度不符或含非十六进制字符的 asset 不得进入 `assets` 可服务候选状态，也不得生成目标库存。

### 10.2 `target_inventory`

`target_inventory` 表示主节点要求某节点最终持有某资产，不表示节点已经持有。

| 字段 | M3 合同 |
| --- | --- |
| `node_id` | 所有已批准且未禁用节点均应有目标库存；离线节点也保留目标 |
| `asset_id` | 必须引用已通过摘要门禁的 `assets` |
| `desired_state` | 至少包含 `required` 与 `remove`，实现可扩展 `held` 等内部状态 |
| `updated_at` | 目标库存重新计算时间 |

同一项目扫描事务中，主节点在写入候选资产后重新计算目标库存并生成缺失或清理任务。事务失败时不得留下资产和目标库存不一致的状态。

### 10.3 `node_tasks`

M3 使用 `node_tasks` 记录同步任务状态。

| `task_type` | 语义 |
| --- | --- |
| `asset_download` | 节点下载、校验并落盘指定资产 |
| `asset_delete` | 节点删除已不在目标库存中的本地资产 |
| `inventory_reconcile` | 节点上报完整库存并触发最终对账 |

任务状态至少覆盖 `pending`、`sent`、`running`、`succeeded`、`failed`、`retry_wait`、`cancelled`。任务写入必须携带 `request_id`；日志和管理查询使用 `task_id` 排障。

### 10.4 `node_inventory`

`node_inventory` 表示主节点已接受的节点本地校验结果。写入或更新为已验证状态前必须同时满足：

1. 报告来自已认证 mTLS 控制通道。
2. 资产存在且当前摘要来自 GitHub 可信 `sha256:`。
3. 节点上报摘要等于 `assets.digest_sha256`。
4. 节点上报大小等于 `assets.size_bytes`。
5. 节点未禁用。

摘要或大小不一致时，主节点必须记录不一致状态并重新生成同步任务；不得把该副本用于最终对账。

### 10.5 `nodes.routing_ready`

M3 是首个允许把 `routing_ready` 置为 `1` 的阶段，但只能在最终对账通过后执行。必须满足：

- 节点未禁用且心跳未超时。
- 当前控制身份有效。
- 该节点所有 `target_inventory.required` 资产均有匹配的已验证 `node_inventory`。
- 没有运行中、失败未处理或等待重试的必需资产任务。
- 最近完整库存报告晚于目标库存最后更新时间。

任一条件失效时，`routing_ready` 必须回到 `0`。M3 的 `routing_ready=1` 只表示同步库存就绪，不代表 M4 公共下载链路已经可用。

### 10.6 下载节点 `local_assets`

下载节点 M3 写入 `local_assets` 只表示本地文件已按任务摘要和大小校验并完成原子落盘。节点不得以自行计算出的摘要创建主节点未知资产；主节点未下发的本地文件只可作为未知或待清理库存报告。

### 10.7 M3 新增运行表

| 表 | 用途 |
| --- | --- |
| `sync_scans` | 记录周期或手动 Release 扫描的任务 ID、项目、状态、接受/拒绝资产数、错误摘要、请求 ID 和完成时间 |
| `local_sync_tasks` | 下载节点本地记录同步任务状态、错误摘要和更新时间，支持断线后排障 |

未来任何表、字段、索引或事务语义变化，必须先更新本文件。

## 11. M4 公共下载链路合同

M4 启用 M1 已预留的挑战和下载授权表，打通网页 ALTCHA、公开 API PoW、节点绑定令牌和下载节点 Range 文件服务。M4 不启用 M5 的额度扣减、流量预留结算、真实流量入账、统计聚合或 SLA。

### 11.1 `challenges`

| 字段语义 | M4 合同 |
| --- | --- |
| `kind` | 只能为 `altcha` 或 `api_pow`；网页端使用 `altcha`，公开 API 使用 `api_pow` |
| `asset_id` | 挑战绑定的下载意图，提交时必须一致 |
| `client_prefix` | 创建挑战时解析出的客户端 IP 前缀，提交时必须一致 |
| `nonce` | 服务端随机挑战材料或其安全表示，不记录可绕过挑战的密钥 |
| `difficulty` | `altcha` 使用 ALTCHA 工作量参数摘要；`api_pow` 使用前导零位数，默认 `23` |
| `expires_at` | 短时有效；过期挑战不得消费 |
| `consumed_at` | 成功提交时在同一事务内写入，防止重放 |

ALTCHA 参数不得写入或解释为 API PoW 前导零位数；API PoW 不得复用 ALTCHA challenge 载荷。

### 11.2 `download_authorizations`

M4 可在授权成功时写入 `download_authorizations`，作为签发令牌和排障依据。该写入不代表 M5 的下载授权次数统计已经启用。

| 字段语义 | M4 合同 |
| --- | --- |
| `id` | 授权 ID，必须进入下载令牌声明 |
| `asset_id` | 绑定单个资产 |
| `node_id` | 绑定单个下载节点 |
| `client_prefix_key` | 绑定客户端 IP 前缀的规范化键 |
| `expires_at` | 令牌有效期截止 |
| `max_bytes` | 该授权允许发送的最大字节数 |
| `range_limit` | 同一授权允许并发 Range 请求数 |
| `request_id` | 主节点签发请求 ID |
| `first_transfer_at` | M4 不更新；M5 再用于“开始传输授权数” |

### 11.3 授权事务

M4 授权事务必须原子完成：

1. 校验挑战未过期、未消费且资产绑定一致。
2. 校验客户端 IP 前缀与挑战一致。
3. 选择 `routing_ready=true`、未禁用、心跳未超时且 `node_inventory` 已验证持有该资产的节点。
4. 写入授权记录并生成签名令牌。
5. 标记挑战已消费。

M4 可调用额度/流量预留接口形状，但这些接口必须为空操作或明确返回未启用；不得扣减 `quota_buckets`，不得写入有效 `traffic_reservations`，不得聚合 `daily_*` 统计。

### 11.4 下载节点数据

下载节点 M4 只可服务 `local_assets` 中状态为已验证、摘要和大小与主节点令牌资产一致且本地文件存在的资产。节点不得因为用户请求缺失文件而回源 GitHub 下载，也不得把本地未知文件暴露为公共下载。

`pending_traffic_events` 在 M4 仍不启用真实流量补报；M5 开始前必须先补充流量事件、幂等确认和断线恢复合同。M4 要求主节点和下载节点通过配置共享同一份 `download_token.signing_key_file`，密钥内容不得入库或写入日志。

### 11.5 M4 不变量

| 不变量 | 验收方法 |
| --- | --- |
| 网页挑战只使用 ALTCHA | 测试网页接口不接受 API PoW nonce |
| API 挑战只使用 SHA-256 前导零 PoW | 测试默认 `23` 位前导零和规范字符串 |
| 授权只选择可路由且已验证持有资产的节点 | SQLite 事务测试覆盖缺失、副本不一致和 `routing_ready=false` |
| 下载令牌绑定资产、节点、客户端前缀、有效期、最大字节、Range 并发和请求 ID | 令牌声明测试和伪造/跨节点/跨资产复用测试 |
| M4 不产生 M5 统计 | 测试授权和下载后 `daily_*`、`traffic_events`、`first_transfer_at` 不被作为统计写入 |
