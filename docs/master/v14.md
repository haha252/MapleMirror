# Master 数据库 v14

## 结构变化

- 新增 `node_availability_rollups`，按节点和时间桶保存 SLA 可用性聚合。
- 新增索引 `idx_node_availability_rollups_window`，用于按时间窗口读取 24h、7d 和 30d SLA。

## 升级器

- `master.V13ToV14`
- 升级时保留旧 `node_availability_samples` 表，并将已有样本按原 `sample_start` 回填为 `bucket_minutes=1` 的 rollup。
- 回填后清理 35 天前的旧样本，避免历史样本继续占用热库空间。
- 裁剪已完成的 `sync_scans`：每个项目保留最近 50 条。
- 裁剪 `traffic_event_dedupe`：按节点当前游标保留最近 10000 个事件序号，并删除过期超过 30 天授权关联的 dedupe 与 reservation。

## 兼容风险

- 旧样本表不删除，旧库升级后仍可保留历史排障数据。
- 新采样路径不再逐条写 `node_availability_samples`，而是写入 `node_availability_rollups`。
- 升级器会删除较旧的扫描、SLA 样本和流量去重窗口数据；这些数据不参与授权、额度或正式流量聚合恢复。

## 验证方式

- 空库启动应创建 `node_availability_rollups` 和 `idx_node_availability_rollups_window`。
- 从 v13 旧库升级后，`database_version(master)` 应推进到 `14`。
- 公共节点列表和管理面 SLA 窗口应从 rollup 表读取可用率。
