# 项目详情页统计实施计划

日期：2026-10-04。状态：已实施，页面与接口验证结果见文末。

## 目标与页面布局

将项目详情页改为左右两栏：左侧承载当前项目介绍和下载操作，右侧展示当前项目的统计卡片和最近 30 天趋势。沿用数据统计页的配色、卡片、数字格式和图表交互。

明确约束：项目页全部统计数据均限定为当前 project_id，包括卡片累计值、近 30 日值、涨跌幅、图表曲线、柱形、图例关联的数值、悬浮提示和定时刷新响应。只复用全站统计页的展示组件；数据由项目统计接口提供，项目页不得调用全站统计接口作为数据来源或失败兜底。切换项目后不得残留前一个项目的数据。

桌面端初始采用约 55% / 45% 的宽度分配，两栏顶部对齐，间距 24px。返回链接位于两栏上方。左侧依次为项目图标与名称、仓库及更新时间、官网入口、文件选择与下载、项目描述；右侧依次为项目统计标题、四张指标卡片、趋势图。

左侧原有图标与下载区需要改成适合半屏宽度的紧凑排版，取消当前 52px 的横向内边距和独立大图标栏，避免将原来的宽版布局简单缩小后产生拥挤。项目描述按正文自然高度展示，取消固定的 212px 最小高度。

右侧卡片采用 2 × 2 排列；趋势图宽度占满右栏，高度初始约 300px。页面宽度不足约 1100px 时改为上下排列，先显示项目内容，再显示统计。手机保留两列紧凑卡片，极窄屏再改成单列。最终断点以长项目名、长文件名和下载选择器的实际显示效果调整。

## 统计内容与口径

| 卡片 | 累计数据 | 近 30 日数据 |
| --- | --- | --- |
| 总下载量 | authorization_count | 最近 30 个统计日的授权次数 |
| 网页下载量 | web_authorization_count | 最近 30 个统计日的网页授权次数 |
| API 下载量 | api_authorization_count | 最近 30 个统计日的 API 授权次数 |
| 总流量 | sent_bytes | 最近 30 个统计日的实际发送字节 |

每张卡片显示累计值、近 30 日值，以及相对于前一个 30 日窗口的变化，风格复用现有数据统计页。趋势解释注明比较的是两个 30 日窗口；前期为零时沿用现有统计页的显示规则。

当前只有全站访问量，没有项目访问量，因此项目统计不展示访问量卡片，也不填入全站访问量。下载量沿用当前系统的成功签发下载令牌次数；总流量包含重传、Range 和中断前发送的数据。按照用户的后续要求，图表下方不展示说明文字、统计时区或更新时间；统计口径记录在接口文档中。

首版统计为整个项目的所有版本与文件合计，下载区域切换版本、系统或架构时，统计不随之筛选。流量归属沿用授权预留统计日及服务端统计时区，不改变入账规则。

## 图表方案

默认展示最近 30 天下载趋势：仅保留 Web/API 堆叠柱形样式，整根柱子的高度表达总下载量，不额外叠加总下载量折线。图例仅标注 Web/API；总下载量继续出现在卡片和每日提示中。全站统计页仍保留原有访问量折线。

图表上方提供“下载量 / 流量”切换：流量视图使用项目每日 sent_bytes 绘制折线，纵轴使用自适应字节单位；避免次数与字节共用同一纵轴。两个视图均支持日期提示，提示中展示当日总下载量、Web/API 下载量及总流量。

日期按服务端统计时区生成，缺失日期补零，始终返回连续 30 天。没有任何统计记录的项目显示零值卡片及“暂无下载数据”提示；读取失败显示错误与重试入口，不能把失败表现成零下载。

沿用 ResizeObserver 自适应尺寸和语言切换重绘，并补充触屏点击与键盘选取日期的方式。主题配色通过现有 CSS 变量控制。

## 后端与接口

1. 新增项目统计查询：累计值读取 project_stat_totals；近 30 日、前 30 日和趋势读取 daily_project_stats，并限定 project_id 与日期范围。项目存在但无统计行时返回零值。
2. 新增 GET /api/public/v1/projects/{projectID}/stats，一次返回项目 ID、统计时区、快照生成时间、四项累计/近 30 日/前 30 日值及连续 30 日趋势。响应采用明确命名字段，复用公开 API 的成功和错误格式。
3. 调整现有 projects/ 路径分发。当前该前缀全部进入 projectAssets，且只识别 /assets，必须增加 /stats 分支并保留资产接口行为。
4. 项目可见性沿用项目页与公开目录的规则；不存在或不公开的项目返回 404，无统计记录的公开项目返回 200 和零值。查询只返回项目汇总。
5. 使用按项目 ID 和统计日隔离的短时缓存，TTL 初始为 5 秒；仅缓存已确认公开的项目，限制缓存大小并清理过期条目。缓存及前端刷新允许现有累计统计缓冲带来的短暂延迟。
6. 首屏项目内容正常渲染，统计独立异步加载；首次加载一次完整快照，页面可见时每 10 秒刷新，并防止请求重叠、旧响应覆盖新响应。隐藏时暂停轮询，恢复可见时立即刷新；刷新失败保留上次数据并标记刷新失败。

本方案使用已有统计表，不需要数据库版本升级或新增索引。查询计划已确认使用现有日期索引限定最近 60 个统计日。

## 实施顺序与验收

1. 实现项目统计查询、接口与缓存，先验证多个项目之间不会串数据、公开可见性和零值处理。
2. 提取可复用卡片及图表组件，让原数据统计页使用它们，并检查全站统计行为。
3. 调整项目页两栏布局，接入卡片、图表、异步加载、语言文案及手机适配。
4. 完成针对性测试与浏览器检查，更新接口文档。

后端测试覆盖累计值、两个 30 日窗口、来源分类、连续日期补零、统计时区跨日、无数据项目、未知及不公开项目、非法路径、请求方法、缓存隔离与过期，以及原 /assets 接口。

浏览器检查覆盖 1440/1920px 桌面、1024px 平板和 375/390px 手机宽度；检查深浅主题、中英切换、长名称及文件名、无描述项目、零数据、接口失败与恢复、提示框边界、触屏与键盘操作。回归条件选择、文件浏览、下载验证入口和全站统计页。

验证命令优先使用 go test ./internal/master/public、相关 JS 的 node --check 和 git diff --check；共用组件及路由变更完成后运行 go test ./...。

验收结果应为：宽屏左侧可以完整完成下载、右侧清晰展示本项目四项统计和趋势；手机无横向溢出；不同项目指标隔离；图表和卡片与数据库口径一致；下载操作和全站统计功能正常。

项目范围验收必须用至少两个数值不同的项目核对：逐一比较卡片累计及窗口值、涨跌幅、30 日各日数据和提示框内容，并确认网络请求使用当前项目 ID。全站总量和其他项目数值不得出现在该项目统计中，加载失败也不得回退到全站数据。

## 已有历史数据的边界

旧版本迁移曾将无法区分来源的历史授权归入 Web，页面沿用数据库现有分类。项目重置流程会删除 daily_project_stats 与 project_stat_totals，因此累计只表示目前保留的项目统计；不得借用保留的全站或节点历史流量补成项目数据。网页/API 各自流量和项目访问量尚无独立日统计，本方案不承诺显示这两类未记录数据。
