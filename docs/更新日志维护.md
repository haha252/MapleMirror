# 更新日志维护

主节点从部署目录下的 `changelog/` 读取公开更新记录。真实记录只保存在部署机，
不会编译进二进制；仓库中的 `configs/changelog.example/` 仅为示例。

## 目录与文件

每个事件使用一个 YAML 文件，并放入对应月份目录：

```text
changelog/
└── 2026-07/
    └── 2026-07-30-1220-changelog-page.yaml
```

推荐文件名为 `YYYY-MM-DD-HHmm-简短标识.yaml`。文件名只用于稳定排序，
实际展示时间以文件内的 `time` 为准。

```yaml
level: "notice"
title: "上线更新日志页面"
time: "2026-07-30 12:20"
description: |-
  新增 **更新日志** 页面，可按等级筛选和搜索。
  旧入口将在 ~~后续版本~~ 中逐步调整。
  详情请查看 [API 文档](https://example.com/api-docs)。
```

字段规则：

- `level` 必须为 `info`、`notice`、`warn` 或 `critical`。
- `title` 必填，最多 200 个 Unicode 字符。
- `time` 必须使用 `YYYY-MM-DD HH:mm`，并按北京时间解释。
- `time` 的年月必须与所在 `YYYY-MM` 目录一致。
- `description` 可为空或多行，只支持 `**加粗**`、`*斜体*`、`~~删除线~~`
  和 `[文字](https://地址)`；加粗会同时显示下划线。
- 链接只允许 `http` 和 `https`，原始 HTML 不会执行。

## 部署与生效

默认目录为可执行文件工作目录下的 `changelog`，也可以显式指定：

```bash
./mirror-master -changelog /srv/mirror/changelog
```

主节点每两秒检测一次目录变化。新增、修改或删除记录后无需重启。
每次变化会先完整校验所有文件，再原子替换内存快照；如果任一文件无效，
页面继续使用上一份有效记录，并在主节点日志中记录出错文件。修复文件后会自动恢复。

目录不存在时页面显示“暂无更新记录”，不会影响主节点启动。为了避免写入一半的文件
被热重载读取，生产环境建议先在同目录写入临时文件，完成后再原子重命名为 `.yaml`。

## 查询与排障

浏览器页面位于 `/changelog`，对应数据接口为：

```text
GET /api/public/v1/changelog?minimum_level=info&limit=20
```

如果新记录没有出现，依次检查：

1. 文件扩展名是否为 `.yaml` 或 `.yml`。
2. 月份目录和 `time` 是否一致。
3. 主节点日志中是否出现“更新日志热重载失败”。
4. 修复后等待两秒并刷新页面。
