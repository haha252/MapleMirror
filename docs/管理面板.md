# 管理面板

> 状态：已实现
> 挂载入口：管理监听根路径 `/` 会跳转到 `/admin/`，未登录时进入 `/admin/login`
> 需求基线：管理 API 仍以 `docs/管理API.md` 为准

## 1. 范围

管理面板是管理 HTTPS 监听器上的 Web 运维台，只服务于管理网络，不属于公开下载站。公共监听不得挂载 `/admin/*`，也不得把 `/api/admin/v1/*` 代理给公网用户。

首版管理面板按以下顺序落地：

1. 登录、会话和防爆破。
2. 只读总览、节点列表、扫描状态和统计。
3. 项目配置管理，包括要镜像的仓库、启用状态、版本保留数量、预发布版本、资产规则、架构和系统识别规则。
4. 节点详情、同步诊断和最近报告。
5. 配对审批、节点禁用/启用、扫描触发、同步重试等高风险操作。
6. 登录封禁、公开下载自动封禁和审计摘要管理。

## 2. 传输与认证

管理面板直接复用 `server.management_listen` 的 HTTPS 服务。启用条件：

- `admin.tls.cert_file` 和 `admin.tls.key_file` 必须有效。
- 来源仍受 `admin.allowed_cidrs` 限制。
- 默认模式下，高风险操作继续要求管理员 mTLS，账号密码不得降级既有管理 API 合同。
- `admin.web.exclusive_api=true` 时，管理监听不挂载原始 `/api/admin/v1/*`；浏览器登录后只通过 `/admin/api/*` 操作。
- `admin.web.high_risk_session_allowed=true` 只能与 `exclusive_api=true` 同时启用，高风险操作由网页登录会话授权，不再要求浏览器客户端 mTLS。

Web 登录使用独立配置：

```yaml
admin:
  web:
    enabled: true
    exclusive_api: true
    high_risk_session_allowed: true
    users_file: "secrets/admin-users.yaml"
    session_secret_file: "secrets/admin-web-session.key"
    session_ttl: "12h"
    login_failure_window: "24h"
    login_failure_limit: 3
    login_ban_duration: "168h"
```

`users_file` 只保存密码哈希，不保存明文密码。`session_secret_file` 保存会话签名密钥，不得写入日志或页面。

若 `users_file` 不存在，主节点启动管理面板时会自动生成首个 PBKDF2-SHA256 密码哈希用户文件。`admin.web.bootstrap_password_env` 指向的环境变量存在且有值时，用户名固定为 `admin`，密码使用该环境变量；否则自动生成 8 位随机用户名和 20 位随机密码，并只输出到当前启动控制台一次，不写入日志文件。生成后应保存控制台显示的初始凭据，清理临时环境变量，并通过面板或后续运维工具维护用户文件。

## 3. 防爆破

同一管理来源 IP 在 `admin.web.login_failure_window` 内密码错误达到 `admin.web.login_failure_limit` 次后，写入 `admin_ip_blocks` 并封禁 `admin.web.login_ban_duration`。默认等价于 1 天内错误 3 次，封禁 7 天。

管理来源 IP 的解析规则与公共入口一致：只有 TCP 对端属于 `proxy.trusted_cidrs` 时才信任 `X-Forwarded-For` 或 `X-Real-IP`；否则使用 TCP 对端地址。管理面板位于可信 nginx 后时，应把 nginx 直连地址加入 `proxy.trusted_cidrs`，并把真实管理员来源网段加入 `admin.allowed_cidrs`。

封禁期内：

- `/admin/login` 和 `/admin/*` 返回统一管理面板错误页。
- 不向外区分用户名不存在、密码错误或来源被封禁。
- 普通日志和审计只记录脱敏来源，不记录完整 IP、密码、Cookie、会话密钥或管理令牌。
- 非受信代理来源伪造的 `X-Forwarded-For` 或 `X-Real-IP` 不影响登录封禁、会话绑定或来源 CIDR 判断。

## 4. 视觉与交互

管理面板复用公开前端的基础视觉变量和主题：

- `web/public/static/base.css`
- `web/public/static/base-responsive.css`
- `web/public/static/theme.js`

管理面板新增 `web/admin/static/admin.css` 和 `web/admin/static/admin.js`。页面保持 8px 圆角、统一主题色、自定义滚动条、明暗主题和中文界面。

交互不得使用浏览器原生 `alert`、`confirm`、`prompt` 或默认表单校验气泡。所有错误、确认、加载和失败状态使用站内状态条、Toast 或自定义弹窗。

## 5. 敏感信息边界

管理面板不得展示：

- 管理令牌、会话密钥、密码哈希。
- 节点私钥、证书私钥、完整 CSR 或证书 PEM。
- 下载令牌、公共下载授权令牌。
- 完整客户端 IP。
- 下载节点本地绝对路径。

每个管理请求和高风险操作必须能通过 `request_id` 与日志或审计事件关联。

## 6. 项目管理

项目管理以 `projects.yaml` 的结构化字段为准，不提供自由文本拼接保存。管理面板读取当前 `ProjectLoader.Current()` 作为展示值；保存时接收完整项目结构，写入同目录临时文件，使用 `config.LoadProjects` 复用现有校验，通过后再替换正式 `projects.yaml`。

保存成功后必须：

- 调用 `ProjectLoader.Load()` 刷新内存配置。
- 调用 `SyncProjectConfig` 同步 `projects` 和 `project_scan_state`。
- 对启用或规则变化的项目设置尽快扫描。
- 对禁用或移除的项目禁用目标库存，不直接删除历史流量统计。

项目保存属于高风险操作：默认模式下非回环来源必须提供管理员 mTLS 客户端证书；`exclusive_api=true` 且 `high_risk_session_allowed=true` 时，由有效网页登录会话授权。页面不得把 GitHub Token、管理令牌或下载令牌作为项目字段展示或保存。

## 7. 页面与操作

当前面板包含以下视图：

- 总览：今日授权、今日传输、今日流量、累计流量、节点状态和项目扫描状态。
- 节点：节点列表、同步诊断、同步重置、禁用和启用。
- 同步：触发全部启用项目扫描。
- 项目：以结构化 JSON 管理要镜像的仓库、规则、版本保留、预发布、架构和系统识别配置。
- 配对：创建一次性配对码，批准或拒绝待登记节点。
- 安全：查看并解除管理登录封禁和公开下载自动封禁。

所有写操作都通过站内自定义确认弹窗确认，不使用浏览器原生 `alert`、`confirm` 或 `prompt`。
