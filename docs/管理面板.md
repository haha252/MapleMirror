# 管理面板

> 状态：已实现
> 挂载入口：管理监听根路径 `/` 会跳转到 `/admin/`，未登录时进入 `/admin/login`
> 需求基线：管理面板是唯一管理入口；裸 `/api/admin/v1/*` 已废止

## 1. 范围

管理面板是管理 HTTPS 监听器上的 Web 运维台，只服务于管理网络，不属于公开下载站。公共监听不得挂载 `/admin/*`，也不得把管理监听器代理给公网用户。

首版管理面板按以下顺序落地：

1. 登录、会话和防爆破。
2. 只读总览、节点列表、扫描状态和统计。
3. 项目配置管理，包括要镜像的仓库、启用状态、版本保留数量、预发布版本、资产规则、架构和系统识别规则。
4. 节点详情、同步诊断和最近报告。
5. 配对审批、节点禁用/启用、扫描触发、同步重试等高风险操作。
6. 登录封禁、公开下载自动封禁和审计摘要管理。

## 2. 传输与认证

管理面板默认复用 `server.management_listen` 的 HTTPS 服务。启用条件：

- `admin.tls.cert_file` 和 `admin.tls.key_file` 必须有效。
- 管理监听不挂载原始 `/api/admin/v1/*`，浏览器登录后只通过 `/admin/api/*` 操作。
- 高风险操作由有效网页登录会话授权，不再要求浏览器客户端 mTLS。
- `admin.web.https_enabled=false` 仅用于 nginx 已终止 HTTPS 的反代部署；后端管理监听必须绑定回环或受控内网地址。

Web 登录使用独立配置：

```yaml
admin:
  web:
    https_enabled: true
    users_file: "secrets/admin-users.yaml"
    bootstrap_password_env: "MIRROR_ADMIN_WEB_PASSWORD"
    session_secret_file: "secrets/admin-web-session.key"
    session_ttl: "12h"
    login_failure_window: "24h"
    login_failure_limit: 3
    login_ban_duration: "168h"
```

nginx 负责 HTTPS 时，可使用：

```yaml
server:
  management_listen: "127.0.0.1:9080"
proxy:
  trusted_cidrs:
    - "127.0.0.1/32"
admin:
  web:
    https_enabled: false
```

此时 nginx 到后端使用 `http://127.0.0.1:9080`，公网侧仍必须使用 HTTPS，并由 nginx 设置可信的 `X-Forwarded-For` 或 `X-Real-IP`。

`users_file` 只保存密码哈希，不保存明文密码。`session_secret_file` 保存会话签名密钥，不得写入日志或页面。

若 `users_file` 不存在，主节点启动管理面板时会自动生成首个 PBKDF2-SHA256 密码哈希用户文件。`admin.web.bootstrap_password_env` 指向的环境变量存在且有值时，用户名固定为 `admin`，密码使用该环境变量；否则自动生成 8 位随机用户名和 20 位随机密码，并只输出到当前启动控制台一次，不写入日志文件。生成后应保存控制台显示的初始凭据，清理临时环境变量，并通过面板或后续运维工具维护用户文件。

## 3. 防爆破

同一管理来源 IP 在 `admin.web.login_failure_window` 内密码错误达到 `admin.web.login_failure_limit` 次后，写入 `admin_ip_blocks` 并封禁 `admin.web.login_ban_duration`。默认等价于 1 天内错误 3 次，封禁 7 天。

管理来源 IP 的解析规则与公共入口一致：只有 TCP 对端属于 `proxy.trusted_cidrs` 时才信任 `X-Forwarded-For` 或 `X-Real-IP`；否则使用 TCP 对端地址。管理面板位于可信 nginx 后时，应把 nginx 直连地址加入 `proxy.trusted_cidrs`，用于登录封禁和会话绑定识别真实来源。

封禁期内：

- `/admin/login` 和 `/admin/*` 返回统一管理面板错误页。
- 不向外区分用户名不存在、密码错误或来源被封禁。
- 普通日志和审计只记录脱敏来源，不记录完整 IP、密码、Cookie 或会话密钥。
- 非受信代理来源伪造的 `X-Forwarded-For` 或 `X-Real-IP` 不影响登录封禁、会话绑定或来源 CIDR 判断。

## 4. 视觉与交互

管理面板复用公开前端的基础视觉变量和主题：

- `web/public/static/base.css`
- `web/public/static/base-responsive.css`
- `web/public/static/theme.js`

管理面板新增 `web/admin/static/admin.css` 和 `web/admin/static/admin.js`。页面保持 8px 圆角、统一主题色、自定义滚动条、明暗主题和中文界面。

交互不得使用浏览器原生 `alert`、`confirm`、`prompt` 或默认表单校验气泡。所有错误、确认、加载和失败状态使用站内状态条、Toast 或自定义弹窗。

后台页面展示的时间统一由 Web 管理接口按 `stats.timezone` 配置时区转换，格式固定为 `yyyy/mm/dd hh:mm`。

## 5. 敏感信息边界

管理面板不得展示：

- 会话密钥、密码哈希。
- 节点私钥、证书私钥、完整 CSR 或证书 PEM。
- 下载令牌、公共下载授权令牌。
- 完整客户端 IP。
- 下载节点本地绝对路径。

每个管理请求和高风险操作必须能通过 `request_id` 与日志或审计事件关联。

## 6. 项目管理

项目管理以 `projects.yaml` 的结构化字段为准，不提供自由文本拼接保存。管理面板读取当前 `ProjectLoader.Current()` 作为展示值；保存时接收完整项目结构，写入同目录临时文件，使用 `config.LoadProjects` 复用现有校验，通过后再替换正式 `projects.yaml`。

保存成功后必须：

- 调用 `ProjectLoader.Load()` 刷新内存配置。
- 调用 `SyncProjectConfig` 同步 `projects` 和 `project_scan_state`。
- 对启用或规则变化的项目设置尽快扫描。
- 对禁用或移除的项目禁用目标库存，不直接删除历史流量统计。

项目保存属于高风险操作，必须由有效网页登录会话授权。页面不得把 GitHub Token、会话密钥或下载令牌作为项目字段展示或保存。

## 7. 页面与操作

当前面板按顶栏板块拆分为独立页面：

- 总览：今日授权、今日传输、今日流量、累计流量、节点状态汇总和扫描异常摘要，只做状态查看和跳转。
- 节点：节点列表、节点详情、同步诊断、最近心跳/库存/压力报告、SLA、节点项目管理、同步重置、禁用/启用、配对码创建和登记审批。
- 同步：项目扫描状态、触发全部或单项目 Release 扫描、最近扫描详情、节点同步任务列表、失败或等待任务重试/取消。
- 项目：以项目卡片管理 `projects.yaml`，支持新增、修改、删除、禁用/启用、重置并重新扫描；新增和修改进入独立页面，按基础信息、运行策略、架构识别、系统识别、包含规则和排除规则分组编辑。
- 安全：按手动封禁、封禁列表、授权排障、流量事件、审计摘要的顺序单列展示；支持手动添加管理登录或公开下载封禁，封禁列表支持分页、多选解除，流量事件和审计摘要也使用分页展示。

项目页不再把 JSON 文本框作为主要操作入口。页面保存时仍提交完整项目结构，由服务端写入同目录临时文件，复用 `config.LoadProjects` 校验，校验通过后替换 `projects.yaml` 并同步运行状态。

所有写操作都通过站内自定义确认弹窗确认，不使用浏览器原生 `alert`、`confirm` 或 `prompt`。

## 8. 节点项目管理

节点详情提供“项目管理”入口，进入 `/admin/nodes/{node_id}/projects`。页面展示节点当前自动分配开关、`max_mirror_projects` 上限、项目列表、最近 30 天下载量、当前是否分配和最近变化时间。

自动模式由主节点按 `daily_project_stats.authorization_count` 热度选择项目：热度窗口为 30 天，已分配项目最短保留 3 天，候选项目需要比当前边缘项目高 20% 以上才替换。关闭自动分配后，管理员可手动勾选项目；保存时服务端校验选择数量不得超过节点上报的最大镜像项目数。保存属于高风险操作，必须由有效网页登录会话授权，并写入审计事件。
