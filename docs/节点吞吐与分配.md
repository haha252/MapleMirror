# 节点吞吐与分配

节点配置的 `target_bandwidth_bps` 是目标带宽，不能代表任意时刻都能交付的带宽。阿里云、腾讯云节点遇到出口限速、共享链路拥塞等情况时，实际吞吐可能停在 1、10、100 Mbps 或其他速率。节点现在被动采集 TCP 交付数据，估计当前有效带宽，并将其用于后续下载授权的节点评分。

这个功能判断的是“有发送需求但吞吐受限”，不能单凭这些数据确定是云厂商限速。它不调用云监控 API，也不发起主动测速。

## 采集与判定

Linux 节点通过 `NETLINK_SOCK_DIAG / INET_DIAG_INFO` 读取已建立 TCP 连接的累计 ACK 字节、忙碌时间、接收窗口受限时间、发送缓冲区受限时间和未发送字节。只有近期通过下载鉴权的客户端 IP 参与计算；同一 IP 的多个 Range 连接只算一个客户端。短连接若在两次采样之间建立并结束，不参与估计。

采样随节点状态报告执行，最小间隔 10 秒；实际窗口可能更长，例如 30 秒心跳。第一次采集只建立基线，需要随后两个连续窗口满足以下条件，才产生有效带宽估计：

- 至少两个不同客户端 IP 的连接持续有待发送数据，TCP 忙碌时间达到窗口的 50%。
- 这些连接因接收窗口、发送缓冲区受限的时间各不超过忙碌时间的 10%，用于排除慢接收端或本机发送缓冲区不足。
- ACK 交付速率和整机实际出口速率均低于目标带宽的 80%。
- 两个连续窗口的 ACK 交付速率相差不超过前一窗口的 12.5%。

有效带宽取当前 ACK 交付速率和整机出口速率的较大值，并以目标带宽为上限。这里没有固定 Mbps 下限。上述百分比是本项目的保守工程初值，并非云厂商提供的确定性限速阈值；流量不足、单个慢客户端或样本缺失不构成新的受限证据。不同客户端仍可能共享同一个下游瓶颈，因此估计并不等于节点出口的精确容量。

采集包括与节点处于同一网络命名空间的本机 Nginx 等反向代理的外侧 TCP 连接。应用返回后客户端关联保留 2 分钟；若代理外侧连接仍有持续发送需求，继续延长关联以跟踪缓冲响应。代理需要正确传递客户端 IP，并在节点配置中设为可信代理。如果代理位于另一台机器或另一网络命名空间，节点无法观测代理外侧的 TCP 交付情况。只支持可见的 TCP 连接，不包含代理外侧的 QUIC/HTTP3。匹配粒度是客户端 IP，可能包含该 IP 与本机的其他 TCP 业务。

## 分配与恢复

原有带宽压力是 `实际出口带宽 / 目标带宽`。受限证据有效时，分配压力取以下三者的最大值：

```text
实际出口带宽 / 目标带宽
实际出口带宽 / min(目标带宽, 估计有效带宽)
0.9
```

例如目标 200 Mbps、实际 1 Mbps、有效带宽 1 Mbps 的节点，分配压力会从 0.5% 变成 100%。现有综合评分继续按压力扣分，再结合下载优先级、地区和活动下载数选择节点。这是降低分配权重，不是禁用节点；若其他节点分数更低，仍可能选中它。已签发的授权继续有效。

0.9 的压力下限防止降权后流量减少，又立刻被误认成空闲。证据最长保留 2 分钟：新的稳定受限窗口可刷新估计；在未满足受限条件时，至少两个客户端的交付速率连续两个窗口达到旧估计的 125%，会提前清除估计。没有足够流量时不会证明恢复，但证据到期后节点可以重新获得分配。新的更高或更低受限平台会更新估计。

旧节点、不支持的操作系统、内核缺少 TCP 计数器、网络诊断权限被容器策略禁用时，继续使用原有带宽压力。采集失败不刷新受限证据。节点与主节点需要保持时间同步，主节点拒绝使用超过自身时间 5 秒的受限时间戳。

## 协议与管理面板

V1 的 `heartbeat.pressure`、`pressure.report` 和 V2 的 `node.status` 增加可选 `download_pressure` 对象。带宽字段统一为 **字节/秒**，与既有协议一致；1 Mbps 对应 125000 字节/秒。

| 字段 | 含义 |
| --- | --- |
| `sampled_at` | 最近一次成功采样时间 |
| `window_seconds` | 实际采样窗口 |
| `observed_peers` | 有 TCP 忙碌时间增量的不同客户端 IP 数 |
| `constrained_peers` | 满足发送需求与端点排除条件的不同客户端 IP 数 |
| `delivery_bandwidth_bps` | 匹配连接的 ACK 交付速率 |
| `effective_bandwidth_bps` | 有效带宽估计；0 表示未知 |
| `limited_at` | 最近确认受限的时间 |

主节点报告接口的 `pressure_ratio` 是实际用于分配的调整后压力，`bandwidth_pressure_ratio` 保留原始带宽比例，`throughput_limited` 表示受限证据当前是否有效。管理面板节点详情显示吞吐状态和估计有效带宽。“未检测到受限或样本不足”不代表确认带宽正常。

需要更新主节点和下载节点才能启用整条链路，无需数据库迁移或新增配置。协议新增字段可选，兼容旧节点。主节点重启会清空运行时状态，节点随后重新报告；下载节点重启会重新建立采样基线。

## 参考

- [Linux TCP UAPI](https://github.com/torvalds/linux/blob/master/include/uapi/linux/tcp.h)：计数器定义。
- [BBR 的 policer 检测](https://github.com/torvalds/linux/blob/master/net/ipv4/tcp_bbr.c)：连续窗口、平台稳定性和排除低需求样本的设计参考。本功能没有实现 BBR 的丢包比例检测，不能作为云厂商限速的直接证据。
- [ShaperProbe，IMC 2011](https://faculty.cc.gatech.edu/~dovrolis/Papers/shaperprobe-IMC11.pdf)：通过速率变化检测流量整形的主动探测研究。本功能采用被动采集，不运行该探测算法。
