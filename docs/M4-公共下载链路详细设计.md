# M4 公共下载链路详细设计

> 状态：已实现，进入 M5 前评估
> 阶段：M4 公共下载链路
> 需求基线：`docs/开发要求.md` 定稿 v1.1（2026-05-27）
> 前置实现：M1 基础骨架、M2 控制面、M3 Release 扫描与同步已完成；M3 最新关键提交为 `297f5cf`。
> 文档作用：记录 M4 已实现的公共页面骨架、网页 ALTCHA、公开 API PoW、下载授权、节点绑定令牌和节点 Range 文件服务；M5 开始前仍需先完成统计、额度与 SLA 的合同文档。

## 1. 阶段边界

M4 的目标是让已同步且 `routing_ready=true` 的资产可以通过主节点授权、单一下载节点服务、短时令牌和 HTTP Range 安全下载。M4 只打通“可下载入口到节点文件传输”的闭环，不实现 M5 的额度扣减、真实流量入账、统计聚合或 SLA。

| 类别 | M4 允许交付 |
| --- | --- |
| 公共页面 | 下载、统计数据、关于、节点状态四个页面的路由、中文骨架和只读展示 |
| 下载页面 | 项目/版本/架构/文件列表、可用性判断、ALTCHA 挑战、下载入口和中文错误 |
| 网页验证 | 自托管 ALTCHA 挑战创建、提交校验、重放拒绝和短时授权 |
| 公开 API | 独立 SHA-256 前导零 PoW 挑战、项目查询、授权领取、授权查询 |
| 授权 | 主节点选择 `routing_ready=true` 且持有已验证资产的节点，签发短时节点绑定下载令牌 |
| 节点下载 | 下载节点校验令牌，只服务本地已验证资产，支持 HTTP Range 与断点续传 |
| 请求关联 | 主节点公共请求、授权、节点下载日志均携带请求 ID，响应返回 `X-Request-ID` |

## 2. M4 明确不实现

| 不实现能力 | 所属阶段 | M4 处理 |
| --- | --- | --- |
| 请求额度扣减 | M5 | 可预留事务接口和拒绝码，不实际扣请求桶 |
| 流量预算预留 | M5 | 可保留 `traffic_reservations` 形状，不实际预留或结算 |
| 真实流量入账 | M5 | 节点可记录本地发送摘要日志，但不写主节点 `traffic_events` |
| 下载授权次数统计 | M5 | M4 签发令牌不更新公开统计聚合 |
| 开始传输授权数统计 | M5 | M4 不维护 `first_transfer_at` 统计口径 |
| 每日/累计流量 | M5 | 统计页面只能显示“未启用”或占位说明 |
| 节点 SLA | M5 | 节点状态页只能展示当前控制/同步状态，不计算 24h/7d/30d SLA |
| 配额封禁策略 | M5 | M4 不实现黑名单、豁免、倍率扣减或日流量上限 |

## 4. 四个公共页面

M4 必须创建四个公共页面的稳定边界，页面文案使用中文，资源使用 UTF-8，前端资源仍受 250 行限制。

| 页面 | M4 内容 | M5 前占位 |
| --- | --- | --- |
| 下载 | 展示项目、版本、架构、文件大小、可用状态、ALTCHA 验证和下载按钮 | 额度耗尽只保留错误码和占位，不做真实额度展示 |
| 统计数据 | 页面路由、标题、说明和未启用状态 | 下载授权次数、开始传输数、每日/累计流量、趋势图均显示“统计尚未启用” |
| 关于 | 服务说明、非官方镜像声明、验证与隐私说明、联系方式配置占位 | 可说明额度和统计将在后续启用 |
| 节点状态 | 当前节点公开名称、同步/离线/禁用/可路由状态、最近更新时间 | SLA、可用率窗口和历史负载显示“统计尚未启用” |

下载页只展示至少一个 `routing_ready=true` 节点已验证持有的资产。若资产存在但没有可路由副本，页面显示“暂不可下载”，不得泄露内部节点地址、磁盘路径或控制面细节。

## 5. 网页 ALTCHA 合同

网页端只使用自托管 ALTCHA，不叠加滑块，也不叠加网页自研 SHA-256 前导零 PoW。ALTCHA 挑战参数来自 `altcha.*`，默认 `altcha.difficulty=22`，不得解释为 API PoW 的前导零位数。

### 5.1 挑战创建

浏览器在下载页选择资产后请求 ALTCHA 挑战。主节点必须：

1. 解析真实客户端 IP，仅在直连来源属于受信代理 CIDR 时接受代理头。
2. 校验资产存在、处于可服务候选状态，并且至少有一个可路由已验证副本。
3. 创建 `kind=altcha` 的短时挑战，绑定 `asset_id`、客户端 IP 前缀、随机量、过期时间和请求 ID。
4. 返回 ALTCHA 组件需要的挑战字段、挑战 ID、过期时间和主节点请求 ID。

### 5.2 挑战提交

浏览器提交 ALTCHA 解决方案后，主节点必须在事务中：

1. 校验挑战存在、未过期、未消费、类型为 `altcha`。
2. 校验挑战绑定的资产和当前请求资产一致。
3. 校验客户端 IP 前缀与挑战创建时一致。
4. 调用 ALTCHA 服务端校验逻辑验证解决方案。
5. 将挑战标记为已消费，防止重放。
6. 进入下载授权流程。

失败时返回中文错误、稳定错误码和请求 ID；不得返回 ALTCHA 密钥、完整客户端 IP 或内部校验细节。

## 6. 公开 API PoW 合同

公开 API 不使用账号体系、API Key 或 ALTCHA 参数。API 客户端必须使用独立 SHA-256 前导零 PoW，默认要求摘要前导 `23` 个二进制零位，参数来自 `api_pow.*`。

API PoW 挑战绑定内容至少包括：

| 字段 | 规则 |
| --- | --- |
| `challenge_id` | 主节点生成，不可预测 |
| `asset_id` | 下载意图，提交时必须一致 |
| `client_prefix` | IPv4 `/32` 或 IPv6 `/128` 起步；M5 再叠加网段额度 |
| `nonce_seed` | 服务端随机量，短时有效 |
| `leading_zero_bits` | 默认 `23`，来自 `api_pow.leading_zero_bits` |
| `expires_at` | 默认来自 `api_pow.challenge_ttl` |
| `algorithm` | 固定 `sha256` |

客户端提交 nonce 后，主节点计算 `SHA-256(challenge_id || asset_id || nonce_seed || nonce)` 或实现中固定的等价规范字符串，并检查前导零位。规范字符串必须写入 `docs/公开API.md` 并由测试固定。

## 7. 下载授权流程

### 7.1 授权前检查

网页 ALTCHA 或 API PoW 校验通过后，主节点执行统一授权流程：

1. 重新加载资产，确认资产仍在保留窗口内且可服务。
2. 查询候选节点：`nodes.routing_ready=true`、未禁用、心跳未超时、`node_inventory` 对该资产为已验证且摘要/大小匹配。
3. 排除当前处于拥塞或近期错误过高的节点；M4 可使用简单排序，M5 再接入压力权重。
4. 若无候选节点，返回“当前没有可用下载节点”。
5. 使用轻量内存限流保护挑战创建；挑战只保存在主节点内存中，过期或消费后清理，不写入数据库。

### 7.2 节点选择

M4 路由选择必须是主节点决策，下载节点不得自行向客户端改派其他节点。基础选择顺序：

1. 优先选择持有该资产且最近心跳正常的 `routing_ready` 节点。
2. 多节点同时可用时，可按压力比、活动下载数、最近错误数和稳定随机因子排序。
3. 选择结果写入授权记录，用于令牌校验和排障。

### 7.3 授权记录

M4 可写入 `download_authorizations`，至少记录：

| 字段 | M4 语义 |
| --- | --- |
| `id` | 授权 ID，作为令牌主体之一 |
| `asset_id` | 绑定资产 |
| `node_id` | 绑定单一下载节点 |
| `client_prefix_key` | 绑定客户端 IP 前缀的规范化键 |
| `expires_at` | 短时有效期 |
| `max_bytes` | 最大可发送字节，至少等于资产大小并保留 Range 重试策略 |
| `range_limit` | 同一授权允许并发 Range 请求上限 |
| `request_id` | 授权链路请求 ID |
| `state` | `issued`、`expired`、`revoked` 等 M4 状态 |

M4 写授权记录不等同于 M5 的“下载授权次数统计”已启用。统计聚合必须等 M5 明确实现。

## 8. 下载令牌合同

下载令牌由主节点签名，短时有效，并只对一个节点、一个资产和一个客户端前缀有效。令牌不得是可被客户端篡改的明文 JSON；可采用 HMAC/JWS/PASETO 等实现，但必须使用服务端密钥签名并带算法版本。

令牌声明至少包含：

| 声明 | 含义 |
| --- | --- |
| `token_version` | 下载令牌版本，如 `download.v1` |
| `authorization_id` | 主节点授权 ID |
| `asset_id` | 资产 ID |
| `node_id` | 绑定下载节点 ID |
| `client_prefix` | 绑定客户端 IP 前缀 |
| `expires_at` | 过期时间 |
| `max_bytes` | 授权最大字节 |
| `range_concurrency_limit` | 允许并发 Range 数 |
| `request_id` | 主节点签发请求 ID |

节点收到令牌后只记录授权 ID、资产 ID、请求 ID 和截断客户端前缀，不记录完整令牌。

## 9. 下载节点文件服务

### 9.1 校验顺序

下载节点公共文件服务收到请求后必须：

1. 生成节点侧请求 ID，并读取主节点授权请求 ID。
2. 校验令牌签名、版本、过期时间、节点 ID 是否等于本节点。
3. 根据直连来源和受信代理规则解析客户端 IP，并校验其属于令牌绑定前缀。
4. 校验 `asset_id` 与请求路径或查询参数一致。
5. 查询 `local_assets`，确认资产状态为已验证、摘要和大小匹配且本地文件存在。
6. 校验并发 Range 数不超过令牌声明限制。
7. 开始传输文件或返回中文错误。

任何校验失败都不得回源 GitHub 下载文件，不得服务未登记在 `local_assets` 的本地文件。

### 9.2 Range 与断点续传

M4 下载节点必须支持标准 HTTP Range：

| 场景 | 行为 |
| --- | --- |
| 无 `Range` | 返回 `200 OK` 和完整文件 |
| 单段 Range | 返回 `206 Partial Content`、`Content-Range`、`Accept-Ranges: bytes` |
| 多线程断点续传 | 同一令牌允许受限并发单段 Range 请求 |
| 无效 Range | 返回 `416 Range Not Satisfiable` 和中文错误摘要 |
| 令牌过期 | 返回 `401` 或 `403`，提示重新授权 |

M4 可以不支持一个 HTTP 请求内的 multipart 多 Range；如不支持，必须返回稳定错误并在公开 API 文档说明。

## 10. 预留 M5 接口

M4 可以在业务层预留下列接口形状，但实现必须为空操作或返回未启用状态：

| 接口 | M4 行为 |
| --- | --- |
| 请求额度检查 | 返回通过或“额度系统未启用”内部状态，不扣减 |
| 流量预算预留 | 不写 `traffic_reservations` 或写入明确未启用状态；不得对外展示为已结算 |
| 授权计数聚合 | 不更新 `daily_project_stats.authorization_count` |
| 开始传输计数 | 不更新 `first_transfer_at` 或开始传输聚合 |
| 流量事件上报 | 不启用控制面流量事件消息，不写 `traffic_events` |
| SLA 样本 | 不生成 `node_availability_samples` 统计结论 |

M5 开始前必须再次更新数据模型、节点协议、管理 API 和公开 API 文档，明确这些预留接口何时从空操作变为真实事务。

## 11. 错误、日志与脱敏

- 所有公共错误响应使用中文 `message`、稳定 `code` 和 `request_id`。
- HTTP 响应返回 `X-Request-ID`；节点下载响应同时可返回 `X-Download-Request-ID` 或等价节点侧关联 ID。
- 日志不得记录完整下载令牌、ALTCHA 密钥、PoW nonce 明文组合、完整客户端 IP、证书私钥、管理令牌或本地绝对路径。
- 可记录截断授权 ID、资产 ID、节点 ID、请求 ID、错误码和脱敏客户端前缀。
- 所有新增源码、配置注释、前端资源、协议 JSON 和文档继续使用 UTF-8。
- 新增 Go、SQL、脚本和前端资源继续受 250 行限制；Markdown 位于 `docs/`，不受该限制。
