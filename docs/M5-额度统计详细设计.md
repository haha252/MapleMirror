# M5 额度统计详细设计

> 状态：已实现，进入 M6 前评估
> 阶段：M5 额度统计
> 需求基线：`docs/开发要求.md` 定稿 v1.1（2026-05-27）
> 前置实现：M1、M2、M3、M4 已完成，M4 收尾提交为 `8b3d2bb`。
> 文档作用：记录 M5 已实现的额度扣减、流量入账、统计聚合、节点 SLA 与页面展示合同；M6 开始前仍需先完成最终加固交付文档。

## 1. 阶段边界

M5 在 M4 已完成的挑战、授权、节点绑定下载令牌和 Range 文件服务基础上，启用中心额度、实际流量入账、授权计数、开始传输计数、统计页和节点 SLA。M5 不改变 GitHub Release 扫描、资产 SHA-256 门禁、节点配对、同步追平和令牌签名的既有安全边界。

| 类别 | M5 交付 |
| --- | --- |
| 请求额度 | IPv4 `/32`、IPv4 `/24`、IPv6 `/128`、IPv6 `/64` 双层桶扣减 |
| 流量预算 | 主节点签发授权前按地址和网段原子预留每日实际流量预算 |
| 授权统计 | 主节点成功签发下载令牌即增加下载授权次数 |
| 开始传输 | 某授权首次产生正字节响应体时，单独增加开始传输授权数 |
| 流量入账 | 下载节点上报真实发送字节，主节点按节点单调事件序号幂等入账 |
| 聚合统计 | 生成每日流量、累计流量、项目维度授权/传输/字节统计 |
| 节点 SLA | 基于路由就绪和心跳状态采集样本，展示 24h、7d、30d 可用率 |
| 页面/API | 统计数据页、节点状态页和公开 API 返回真实统计字段及稳定拒绝码 |

## 2. M5 不改变的边界

| 事项 | 约束 |
| --- | --- |
| 私有仓库 | 仍不支持 |
| 摘要可信源 | 仍只接受 GitHub `digest` 中的 `sha256:` |
| 验证方式 | 网页仍为 ALTCHA；公开 API 仍为 SHA-256 前导零 PoW |
| 下载令牌 | 仍由主节点签发，绑定单一节点、资产、客户端前缀和有效期 |
| 下载节点权限 | 节点不得绕过主节点自行签发、改派或回源服务用户下载 |
| 流量口径 | 只按节点真实发送给客户端的响应体字节统计 |
| 管理页面 | 首版仍不新增管理前端；管理能力通过受保护 API 提供 |

## 4. 请求额度扣减规则

### 4.1 客户端作用域

主节点只在直连来源属于 `config.yaml` 的受信代理 CIDR 时解析转发头；否则使用 TCP 对端地址。规范化后的客户端 IP 同时映射为地址级和网段级两个作用域。

| 客户端 | 地址级作用域 | 网段级作用域 |
| --- | --- | --- |
| IPv4 | `ipv4_32:<a.b.c.d>/32` | `ipv4_24:<a.b.c.0>/24` |
| IPv6 | `ipv6_128:<规范IPv6>/128` | `ipv6_64:<前64位规范前缀>/64` |

### 4.2 桶默认值

| 桶 | 默认容量 | 完全恢复时间 |
| --- | --- | --- |
| IPv4 `/32` | `120` | `48h` |
| IPv4 `/24` | `600` | `48h` |
| IPv6 `/128` | `120` | `48h` |
| IPv6 `/64` | `600` | `48h` |

M5 使用令牌桶语义。桶余额可用微单位整数存储，避免小数累积误差；扣减前按 `updated_at` 和配置恢复速率补充余额，最多恢复到容量。

### 4.3 扣减倍率

项目下载倍率只扣请求额度，不放大每日流量预留，不放大实际流量统计。

| 示例 | 请求额度扣减 | 流量统计 |
| --- | --- | --- |
| 项目倍率 `1`，一次授权 | `/32` 或 `/128` 扣 `1`，对应 `/24` 或 `/64` 扣 `1` | 按节点真实发送字节 |
| 项目倍率 `3`，一次授权 | 地址级和网段级均扣 `3` | 仍按节点真实发送字节，不乘以 `3` |
| Range 重试 | 不再次扣请求额度，除非重新领取新授权 | 每次已发送字节均入账 |

同一授权必须同时检查地址级和网段级请求桶，任一不足即拒绝签发令牌，两个桶均不得被部分扣减。

## 5. 每日流量预算预留

### 5.1 默认上限

| 作用域 | 默认每日实际传输上限 |
| --- | --- |
| IPv4 `/32` | `3 GiB` |
| IPv4 `/24` | `20 GiB` |
| IPv6 `/128` | `3 GiB` |
| IPv6 `/64` | `20 GiB` |

统计日按配置时区计算，默认 `Asia/Shanghai`。M5 必须用同一统计日计算预留、结算和日聚合。

### 5.2 预留字节

签发授权时，主节点按资产大小和令牌 `max_bytes` 计算本次授权可能消耗的最大实际字节。预留同时占用地址级和网段级日预算。

| 情况 | 规则 |
| --- | --- |
| 完整下载授权 | 预留 `max_bytes`，通常等于资产大小 |
| 断点续传或 Range | M5 不在签发时猜测 Range，只按授权最大可发送字节预留 |
| 令牌过期未使用 | 预留可在过期清理任务中释放或标记关闭 |
| 真实发送少于预留 | 入账时按真实字节结算，剩余预算可释放 |
| 真实发送超过预留 | 节点不得超过令牌 `max_bytes`；超出事件记安全异常，不放大统计 |

## 6. 授权事务

网页 ALTCHA 或公开 API PoW 校验通过后，主节点必须在同一数据库事务中原子完成：

1. 重新校验挑战未过期、未消费、资产绑定和客户端前缀一致。
2. 重新校验资产仍处于可服务状态，并选择 `routing_ready=true`、未禁用、心跳未超时且已验证持有资产的节点。
3. 计算项目下载倍率，补充并检查地址级和网段级请求额度。
4. 检查地址级和网段级每日流量预算，写入授权级流量预留。
5. 写入 `download_authorizations`，状态为 `issued`。
6. 将挑战标记为已消费。
7. 更新项目当日下载授权次数。
8. 生成签名下载令牌并提交事务。

任一步失败时，事务整体回滚。不得出现挑战已消费但未签发授权、请求桶被扣但无授权、授权已签发但无流量预留的中间状态。

## 7. M4 已签发下载令牌链路接入

M5 上线后，所有新签发授权必须经过 M5 额度事务。M4 已签发且仍未过期的下载令牌按兼容策略处理：

| 情况 | 处理 |
| --- | --- |
| 令牌对应授权缺少有效流量预留 | 下载节点仍可按签名与本地资产规则服务；首次流量事件上报时主节点按兼容入账路径补建或标记 `legacy_m4` 预留 |
| 兼容入账发现当日预算已耗尽 | 不回滚已发送字节；后续同授权新请求可被撤销或拒绝，响应 `TRAFFIC_LIMIT_EXCEEDED` |
| 令牌过期、跨节点、跨资产、跨前缀 | 继续按 M4 规则拒绝 |
| M5 部署后新授权 | 不允许走兼容路径，必须存在请求额度扣减和流量预留 |

公开拒绝码应稳定为：

| HTTP 状态 | 错误码 | 场景 |
| --- | --- | --- |
| `429` | `REQUEST_QUOTA_EXHAUSTED` | 地址级或网段级请求额度不足 |
| `429` | `TRAFFIC_LIMIT_EXCEEDED` | 地址级或网段级每日流量预算不足 |
| `409` | `NO_ROUTABLE_NODE` | 无可用下载节点 |
| `401` | `DOWNLOAD_TOKEN_INVALID` | 令牌无效、过期或签名不符 |
| `403` | `CLIENT_PREFIX_MISMATCH` | 客户端前缀不匹配 |
| `409` | `AUTHORIZATION_REVOKED` | 授权已被主节点撤销 |

## 8. 下载授权次数与开始传输授权数

### 8.1 下载授权次数

下载授权次数以主节点成功签发下载令牌计数。计数发生在授权事务提交前，随授权写入和额度扣减同事务提交。

不增加下载授权次数的情况：

- 同一令牌下多线程 Range。
- 同一令牌断点续传。
- 下载节点重试上报流量事件。
- 授权查询接口调用。

### 8.2 开始传输授权数

开始传输授权数以某授权首次产生正字节响应体计数，必须与下载授权次数分离。主节点处理流量事件时，若该授权 `first_transfer_at` 为空且事件 `sent_bytes > 0`，则在同一入账事务中：

1. 设置 `download_authorizations.first_transfer_at`。
2. 将对应项目和统计日的 `transfer_started_count` 增加 `1`。
3. 入账本次真实发送字节。

重复事件、零字节事件、错误响应和仅发送响应头不得增加开始传输授权数。

## 9. 下载节点流量事件

下载节点必须上报真实发送给客户端的响应体字节，不能使用 `Content-Length` 预估替代。每个事件至少包含：

| 字段 | 说明 |
| --- | --- |
| `node_id` | mTLS 控制身份映射的节点 ID |
| `event_sequence` | 节点本地持久化、严格单调递增的流量事件序号 |
| `authorization_id` | 下载令牌中的授权 ID |
| `node_request_id` | 下载节点处理该 HTTP 下载请求生成的请求 ID |
| `master_request_id` | 主节点签发授权时写入令牌的请求 ID |
| `asset_id` | 下载资产 ID，用于校验与排障 |
| `sent_bytes` | 本事件新增真实响应体字节，必须为非负整数 |
| `range_start`、`range_end` | 可选，记录本次 Range 覆盖范围 |
| `status` | `partial`、`completed`、`aborted`、`failed` 等传输结果 |
| `reported_at` | 节点生成事件的 UTC 时间 |

节点必须在本地 `pending_traffic_events` 持久化未确认事件。主节点确认到某个 `event_sequence` 后，节点才能标记 `confirmed_at` 或清理。断线重连后，节点按序补报所有未确认事件。

## 10. 主节点幂等入账

主节点以 `(node_id, event_sequence)` 作为流量事件幂等主键。

| 场景 | 主节点处理 |
| --- | --- |
| 首次事件 | 校验节点身份、授权、节点绑定、资产和请求关联后写入 `traffic_events` 并聚合 |
| 重复事件，内容一致 | 返回已确认，不重复增加统计 |
| 重复事件，内容不一致 | 拒绝并记录安全告警，不覆盖原事件 |
| 序号小于已确认 | 返回幂等确认 |
| 序号跳跃 | 可接受补报窗口内乱序写入，但确认游标不得越过缺口；超出窗口记录协议告警 |
| 授权不存在 | 拒绝入账并保留节点事件待人工排查 |
| 授权已过期 | 已真实发送的字节仍入账；后续可触发撤销 |

流量入账事务必须同时完成：

1. 写入或确认 `traffic_events`。
2. 更新 `traffic_reservations.settled_bytes`。
3. 首次正字节时设置 `first_transfer_at` 并增加开始传输授权数。
4. 更新每日地址/网段流量统计。
5. 更新项目每日真实发送字节。
6. 更新授权状态或最后入账时间。

## 11. 聚合统计口径

### 11.1 每日流量

每日流量按配置时区切分统计日，按节点真实发送字节汇总。重传、重复 Range、中途中断前已经发送的字节均计入；未发送响应体的失败请求不计入。

### 11.2 累计流量

累计流量为所有已幂等入账 `traffic_events.sent_bytes` 的总和，可从每日统计求和或维护只读缓存。累计流量不受项目下载倍率影响。

### 11.3 项目维度统计

项目维度以授权绑定资产反查 Release 和项目：

| 字段 | 口径 |
| --- | --- |
| `authorization_count` | 当日主节点成功签发下载令牌次数 |
| `transfer_started_count` | 当日首次产生正字节响应体的授权数 |
| `sent_bytes` | 当日该项目所有授权真实发送字节 |

### 11.4 节点 SLA 样本

节点 SLA 样本由主节点定期采集，不由节点自报决定。每个样本记录窗口内：

| 字段 | 口径 |
| --- | --- |
| `routable` | 节点未禁用、`routing_ready=true` 且未被调度隔离 |
| `heartbeat_ok` | 最近心跳未超过超时阈值 |
| 可用样本 | `routable=true` 且 `heartbeat_ok=true` |

SLA 窗口至少包含近 `24h`、`7d`、`30d`。样本不足时公开页面必须显示“统计样本不足”，不得把缺失样本当作 100% 可用。

## 12. 页面展示

### 12.1 统计数据页

M5 后统计数据页展示：

- 下载授权次数。
- 开始传输授权数。
- 当日实际流量。
- 累计实际流量。
- 历史每日流量趋势。
- 按项目聚合的授权次数、开始传输数和实际流量。
- 统计时区和最近更新时间。

不得展示：

- 完整客户端 IP 或网段明细。
- 单个授权 ID 列表。
- 单个请求 ID 列表。
- 额度桶精确剩余额度。
- 节点内部地址、磁盘路径或控制面信息。

### 12.2 节点状态页

M5 后节点状态页展示：

- 公开节点名称。
- 当前公开状态，如“同步中”“在线”“繁忙”“离线”“禁用”。
- 是否同步就绪。
- 最近更新时间。
- 负载分档，如“空闲/正常/繁忙”。
- 近 `24h`、`7d`、`30d` SLA。
- 样本不足提示。

不得展示：

- 真实带宽目标。
- 实时内部压力原始值。
- 管理监听地址、控制通道地址或证书信息。
- 本地磁盘路径。
- 完整客户端 IP、下载令牌、管理令牌或流量事件明细。

## 13. 管理 API 查询

M5 可新增只读管理 API，用于运维排障和统计核验。所有路由仍只挂载管理监听器，仍要求管理网络、Bearer 管理令牌，高风险操作仍要求管理员 mTLS。

| 路由 | 鉴权 | 输出 |
| --- | --- | --- |
| `GET /api/admin/v1/stats/overview` | 普通管理查询 | 授权数、开始传输数、当日/累计流量、最近聚合时间 |
| `GET /api/admin/v1/stats/projects?day=YYYY-MM-DD` | 普通管理查询 | 项目维度统计 |
| `GET /api/admin/v1/nodes/{node_id}/sla` | 普通管理查询 | 24h/7d/30d SLA、样本数 |
| `GET /api/admin/v1/authorizations/{authorization_id}` | 普通管理查询 | 单授权状态、脱敏客户端前缀、已入账字节、请求 ID |
| `GET /api/admin/v1/traffic/events?authorization_id=...` | 普通管理查询 | 脱敏事件摘要，仅用于排障 |

管理 API 可以展示脱敏客户端前缀和请求 ID，但不得返回完整令牌、完整 IP、管理凭据、证书正文或本地路径。

## 14. 公开 API 变化

公开 API M5 后不再返回 `QUOTA_NOT_ENABLED`。授权接口可能新增：

| HTTP 状态 | 错误码 | 中文消息示例 |
| --- | --- | --- |
| `429` | `REQUEST_QUOTA_EXHAUSTED` | `请求额度不足，请稍后再试` |
| `429` | `TRAFFIC_LIMIT_EXCEEDED` | `今日流量额度不足，请稍后再试` |
| `409` | `AUTHORIZATION_REVOKED` | `下载授权已失效，请重新领取` |

授权查询可返回：

```json
{
  "authorization_id": "授权标识",
  "asset_id": "资产标识",
  "node_id": "脱敏节点标识",
  "state": "issued",
  "expires_at": "2026-05-28T12:05:00Z",
  "bytes_accounting_enabled": true,
  "sent_bytes": 1048576,
  "first_transfer_at": "2026-05-28T12:01:00Z"
}
```

## 15. 错误、请求 ID 与脱敏

- 所有新增错误使用中文 `message`、稳定 `code` 和 `request_id`。
- HTTP 响应继续返回 `X-Request-ID`。
- 节点下载响应继续返回节点侧请求 ID，并携带主节点授权请求 ID。
- 日志不得记录完整下载令牌、ALTCHA 密钥、PoW 规范字符串、完整客户端 IP、管理令牌、证书私钥或本地绝对路径。
- 可记录授权 ID 截断值、资产 ID、项目 ID、节点 ID、节点请求 ID、主节点请求 ID、错误码和脱敏前缀。
